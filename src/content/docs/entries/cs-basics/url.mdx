## 定义

URL（Uniform Resource Locator，统一资源定位符）是一种标准化的文本字符串，用来在互联网上唯一标识并定位一个资源——它不仅说明资源"在哪里"（服务器地址与路径），还说明"怎么去取"（使用什么协议）。网页、图片、视频、API 端点、文件，凡是在网上能被访问到的东西，都有自己的 URL。日常口语中的"网址""链接"指的通常就是 URL。

## 第一性

> 给互联网上的每个资源分配一个格式统一的地址——先写明"用什么方式取"，再写明"去哪取"。

## 比方

> 全球统一的收货地址格式：协议是"用哪家快递"（顺丰还是 EMS），域名是"城市和小区"，路径是"几栋几单元几零几"，查询参数是快递单上的备注。全世界任何人按这个格式写地址，快递员（浏览器）都能把东西取回来。

## 英文术语拆解

| 英文词 | IPA 音标 | 词性 | 中文含义 | 在本术语中的含义 |
|--------|----------|------|----------|------------------|
| Uniform | /ˈjuːnɪfɔːrm/ | adj. | 统一的；一致的 | 拉丁语 *unus*（一）+ *forma*（形式）；所有资源用同一种格式书写地址，不因资源类型而异 |
| Resource | /rɪˈsɔːrs/ | n. | 资源 | 拉丁语 *resurgere*（重新涌现）；此处指互联网上任何可标识、可访问的对象——文档、图片、服务、数据 |
| Locator | /loʊˈkeɪtər/ | n. | 定位器 | 拉丁语 *locare*（放置）→ *locate*（定位）；指明资源所在位置的东西 |

### 组合理解

三个词的组合含义为"用统一格式书写的资源位置指示符"。核心词是 **Locator**（定位）——URL 的首要任务是给资源"定位置"，告诉机器去哪里找；**Uniform**（统一）是它能普及的关键——正因为全网用同一套书写规则，任何浏览器拿到任何 URL 都能解析。**Resource** 则界定了它的管辖范围：不只网页，一切可寻址的互联网对象都算。这个概念由 Tim Berners-Lee 在 1990 年前后设计万维网时提出（早期曾叫 UDI，Universal Document Identifiers），1994 年 12 月以 RFC 1738 正式成为标准。

## 详细说明

### 一条 URL 的解剖结构

```
https://user@www.example.com:443/docs/search?q=url&lang=zh#第二节
\___/   \__/ \_____________/ \_/ \__________/ \____________/ \____/
 协议   用户信息    域名       端口    路径         查询参数      片段
scheme userinfo   host      port    path        query       fragment
```

| 组成部分 | 作用 | 备注 |
|----------|------|------|
| 协议（scheme） | 用什么方式访问资源 | 常见 http、https、ftp、mailto、file；https 表示加密的 HTTP |
| 用户信息（userinfo） | 可选的身份信息 | 现已极少使用，因明文写在地址里有安全风险 |
| 域名（host） | 资源所在的服务器 | 也可以是 IP 地址；域名靠 DNS 翻译成 IP |
| 端口（port） | 服务器上的具体服务入口 | http 默认 80、https 默认 443，默认端口通常省略不写 |
| 路径（path） | 资源在服务器上的具体位置 | 层层递进的层级结构，如 /docs/search |
| 查询参数（query） | 以 ? 开头的键值对，给服务器传额外指令 | 多个参数用 & 连接，如 ?q=url&lang=zh |
| 片段（fragment） | 以 # 开头，定位资源内部的某个位置 | 只在浏览器本地生效，不会发给服务器 |

### URI、URL、URN 的关系

三者经常混用，标准里的严格区分是：

- **URI（统一资源标识符）**：总称，凡是标识资源的字符串都是 URI
- **URL（定位符）**：URI 的子集，既标识资源、又给出找到它的方法（协议 + 位置）
- **URN（名称符）**：URI 的子集，只给资源一个永久名字，不管它在哪，如 urn:isbn:0451450523（某本书的 ISBN）

打个比方：URL 是"张三住在北京朝阳区某路 5 号"（能找到人），URN 是"张三的身份证号 110……"（只确认身份）。日常说"网址"时大家说的都是 URL，技术上它同时也必是 URI。

### 百分号编码（Percent-Encoding）

URL 只允许使用有限的 ASCII 字符。空格、中文、特殊符号直接放进 URL 会引起解析混乱，因此规定了一种转义机制：把不允许出现的字节改写成 **% + 两位十六进制数**。

- 空格 → %20
- 中文"你"（UTF-8 编码为 E4 BD A0 三个字节）→ %E4%BD%A0

这就是为什么复制带中文的链接时会看到一长串 % 开头的乱码——内容没有变，只是按规则换了种写法，浏览器会自动解码还原。

### 工作原理：从输入 URL 到看到网页

1. **解析**：浏览器拆解 URL，得到协议、域名、路径等部分
2. **寻址**：通过 DNS 把域名翻译成服务器的 IP 地址
3. **连接**：按协议与服务器建立连接（https 还要先完成 TLS 加密握手）
4. **请求**：把路径、查询参数等打包成 HTTP 请求发给服务器
5. **响应**：服务器返回资源（HTML、图片、数据……），浏览器渲染呈现

### 历史与标准演进

- **1990–1991**：Tim Berners-Lee 在 CERN 设计万维网时创造了 URL，最早的 URL 随 1991 年万维网公开声明亮相
- **1994 年 12 月**：RFC 1738 发布，URL 首次成为正式互联网标准，定义了 http、ftp、mailto 等常见方案的语法
- **2005 年**：RFC 3986 将 URL 纳入更通用的 URI 框架，成为现行通用语法规范
- **至今**：浏览器实际遵循 WHATWG 维护的 URL Living Standard（持续更新的"活标准"），它在 RFC 3986 基础上对齐了各大浏览器的真实实现；中文等非 ASCII 字符的直接使用则由 IRI（国际化资源标识符，RFC 3987）扩展支持

## 相关概念

- **URI / URN**：URL 的上位概念与兄弟概念，详见上文"URI、URL、URN 的关系"
- **DNS**：域名系统，负责把 URL 中的域名翻译成 IP 地址，是 URL 能找到服务器的幕后功臣
- **HTTP / HTTPS**：URL 中最常见的协议方案，决定了"用什么方式取资源"
- **[API（应用程序接口）](../dev-tools/api/)**：REST API 用 URL 路径表达资源的层级与身份，URL 设计是 API 设计的核心
- **[Nginx](../infra/nginx/)**：Web 服务器/反向代理软件，日常工作就是接收 URL 请求并决定把它转发或响应给谁
- **IRI**：URL 的国际化扩展，允许地址中直接使用中文等 Unicode 字符
